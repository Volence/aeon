## 3. Part B — the fix (2 site-group commits)

**Site-group A — `bd91b48` (buffers.asm + macros.asm):**
`queueStaticDMA` now signals drop via carry (SET=full/dropped, CLEAR=enqueued), mirroring
`QueueDMA_Critical`. `Enqueue_Dirty_Buffers` clears each `Palette_Dirty` bit / the
`Sprite_Table_Dirty` flag ONLY on carry-clear (`bcs.s`→skip leaves it set to retry next
VBlank). **Rider #1:** the macro edit moves bytes at ALL 7 expansion sites incl. the two
self-healing HScroll ones (they don't read carry — harmless there); the byte-gate/ripple
evidence below covers all 7. HScroll enqueues have no dirty flag (re-queued every frame) →
self-healing → out of scope by design.

**Site-group B — `c1449b9` (load_art.asm):**
The `QueueDMA_Critical` carry is now consumed IMMEDIATELY after the call — **before**
`VSync_Wait`, which clobbers CCR and d0 (rider #2). Drop semantics = DEBUG-fatal + honest
release-retry: DEBUG `RaiseError` (a full Critical queue at blanked-init is unexpected — the
extended VBlank drains Critical every VSync); release drains a frame and retries the same
page (the decompressed bytes still sit in `Art_Staging_Buffer`; a6 unchanged). Length stashed
in **d7** (QueueDMA clobbers d4) for the retry. The drop handler is **out of line** (after
the `rts`) so the loop's forward `.s` branches (`beq.s .done`/`.next`) stay in range in BOTH
shapes despite the DEBUG RaiseError expansion (>128 B) — no forced `.w`.
