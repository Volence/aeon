# Walks that find source must count THIS checkout only (`parcel/test-walk`), 2026-09-13

Branch `parcel/test-walk`, base `d71af34c`, fix commit `89e48936`. Closes item 4 of
`docs/DEFERRED_WORK.md` "CHAR-6 LEFT THREE THINGS OPEN, AND A BUILD CHECK COUNTS SOURCE IN NESTED
COPIES OF THE TREE" (annotated in place). A record: coordinates below are frozen at `89e48936`.

**The defect, as booked.** `tools/test_system_pool_release_empty.py`'s `_emp_sources()` walked the
whole checkout, so a worktree registered as `.aeon-land-cv` inside the main folder was counted as
source: the release test expected 2 System-pool compares (`engine/objects/core.emp:273` twice)

in emp_helper_closure.py's tree scan", which is now false; reworded. New:

## 2. The enumeration form, and what the scratch repo showed

Experiment (git 2.55.0, a scratch `git init` in the session scratchpad, never the real
checkout): one tracked `engine/objects/core.emp`, plus an untracked `engine/objects/untracked.emp`,
a gitignored `ignored_gen/gen.emp`, a nested CLONE (`nested_clone/`, `.git` is a directory), a
nested WORKTREE (`.nested_wt/`, `.git` is a regular file), and a plain untracked copy
(`plaincopy/engine/objects/core.emp`, no `.git`).

    == --cached --others --exclude-standard
    .nested_wt/
    engine/objects/untracked.emp
    nested_clone/
    plaincopy/engine/objects/core.emp
    .gitignore
    engine/objects/core.emp
    == same, with pathspec '*.emp'
    engine/objects/untracked.emp
    plaincopy/engine/objects/core.emp
    engine/objects/core.emp

So git treats a nested worktree or clone as ONE directory entry and never lists its files
(with a `*.emp` pathspec the entry disappears). It DOES list a plain untracked copy. And
`--exclude-standard` drops the gitignored `ignored_gen/gen.emp`.

Chosen form: keep the disk walk, and prune each child directory by sigil's own nested-checkout
rule (`crates/sigil-frontend-emp/src/resolve/manifest.rs`, `is_nested_checkout_dir`: a child
named `.worktrees`, or holding a `.git` entry). Why:

* It is the assembler's definition. `sigil build` finds modules with the same walk and the same
  prune, and reads the DISK, not the index: an untracked or gitignored `.emp` under the root is
  in its scan. A `git ls-files --cached --others --exclude-standard` population would drop a
  gitignored `.emp` that sigil reads. The new population is the old one minus nested checkouts,
  exactly (sections 3 and 4 measure that on this tree).
* It already existed in Python: `tools/artifact_provenance.py`'s `scan_members` reproduced the
  rule inline to digest sigil's scan. It is now one function there, `is_nested_checkout_dir`,
  and every fixed walk imports it.
* It needs no git. Whether a tool must run without git: every build path already calls git
  (`build.sh` asks `git -C "${SIGIL_SRC}" rev-parse` for the assembler revision, and the STRESS
  path restores from git), so a git-less tarball build is not a case this repo has. The choice
  does not rest on that.

Both forms still count a PLAIN untracked copy (no `.git`). So does sigil, which would then
declare every module twice and fail the build first, so the test and the build agree there.

## 7. Open calls and what this does not cover

* **Walk-plus-prune, not `git ls-files`, although the booked fix said `git ls-files`.** Section 2
  and section 3 are the reason; `test_own_untracked_and_ignored_sources_still_count` holds it.
