## The key, in anchor-mover form

**`base_swap`** — a top-level preset-document key, sibling to `bands`/`ramp`, occupying
the SAME `EffectsPreset.ep_raster` channel (exactly one of `bands`/`ramp`/`base_swap` per
document; carrying more than one, or none, is refused). A single closed object:

```json
"base_swap": { "line": 160, "target": 57344 }
```

- **`line`** — the screen line the swap fires on (one `OP_SET_REG` raster op). **Authored
  range is `fire()`'s own ensure** (`engine/effects/raster_dsl.emp:360-361`) — NOT restated
  in `tools/effects_gen.py`, which forwards the value verbatim.
- **`target`** — the raw VRAM byte address Plane A's base register (VDP reg $02) is
  re-pointed at. **The `$2000` granule is the constraint, not a taste bound**: reg $02
  encodes only the address bits above `$2000` and drops the rest silently, so an unaligned
  `target` would point the VDP at a different address than every other `VRAM_*` consumer
  with nothing else visibly wrong. **Enforced by `vdp_base_reg(VdpBase.PlaneA, target)`'s
  own ensure** (`engine/vdp.emp:116-117`), which names the granule (`$2000`) in its refusal
  message — a build-time failure by name, never a silently wrong register byte. No storage
  width note is owed here: `target` is forwarded as a plain comptime `int`, never packed
  into a narrower field on this path.
- **Absent key: no swap.** The section's raster channel is whatever `bands`/`ramp` says
  instead, or `Raster_Program_None` if neither is bound — the same "absent = keep/off,
  never a silent default" rule `rasterRef`/`ramp` already establish.

**No capability bit gates it.** Unlike `ramp`'s `CAP_DENSE_TIER`, `OP_SET_REG` dispatches
unconditionally in every game (it is `fire()`'s cheapest op, not a gated tier), so no
`ensure(Game.SCANLINE_CAPS & CAP_...)` is re-emitted at the generated call site — a real
asymmetry with `ramp`, stated so a reader does not assume one by analogy.

## What binds it on a real section's path, and how that was proved

`games/sonic4/data/editor/effects/presets/ojz_sec6_baseswap.json` (`base_swap: {line: 160,
target: 57344}`, i.e. `VRAM_PLANE_B` = `$E000`) is bound via
`games/sonic4/data/editor/ojz/act1/section_6.meta.json`'s `rasterRef`. The generator lowers
it to `raster_program([fire(160, [reg_set($8200 | vdp_base_reg(VdpBase.PlaneA,
57344))])])` — the SAME three calls (`fire`/`reg_set`/`raster_program`) the hand-authored
`OJZ_BaseSwap` fixture already makes, reused rather than reimplemented. `OJZ_Preset_Sec6`
threads it through `ojz_act1_sec_raster(sec: 6, hand: Raster_Program_None)`, and
`act_descriptor.emp`'s section-6 `ojz_sec(...)` binds `effects: OJZ_Preset_Sec6` — a real
Act 1 section's per-frame path, not a debug hotkey. Unlike `OJZ_BaseSwap`, this emission is
**not** DEBUG-gated: `EditorRaster_OJZ_Act1_ojz_sec6_baseswap` is unconditional `pub data`
and reaches both `s4.bin` and `s4.debug.bin`. `tools/effects_seam_gate.py --source-only`
and `python3 tools/effects_gen.py check` both verify the seam and the generated bytes
before any build; `./build.sh`'s listing (`s4.lst`) is the build-time proof the label
reaches ROM.
