### 4a. Task 9 — assets + def + THE PALETTE DECISION

Assets are already staged (`games/sonic4/data/characters_staging/`, generated by
`gen_characters.py`, which already has a `knuckles` set and deliberately EXCLUDES
him from the Tails palette re-index — that exclusion is correct, see below).

**THE PALETTE — decision already made, implement it.** Knuckles **cannot** be fixed
the way Tails was. Tails worked because his art was a lossless *permutation* of
colours we already had. **Knuckles' art uses S3K index 5 (`$0080`) for ~3,450
pixels, and that colour is absent from our line 0.** Measured. So he needs a real
palette swap, exactly as S3K does (`sonic3k.asm:7663` swaps `Pal_Knuckles` into
CRAM line 0 for him).

**Implement: a per-character palette in the record.**
- Add `cd_palette` to `CharacterDef` (`engine/structs.emp`) — pointer to a 32-byte
  CRAM line, or 0 meaning "leave the current line 0 alone".
- Sonic and Tails → 0 or the existing `art/palettes/SonicAndTails.bin`. **Sonic must
  come out byte-identical** — if pointing him at the existing palette changes a
  single byte of behaviour, use 0 for him instead.
- Knuckles → the staged `characters_staging/palettes/knuckles_main.bin` (32 B; it
  differs from S3K line 0 at indices 2,3,4 only — the per-character body slot).
- Load it on character resolve. `Player_RefreshPhysics` is the **verified single
  chokepoint** for character changes (both `Player_Init` and `Debug_CharacterHotkey`
  route through it) — that is where `Camera_Curl_Offset` is written, so follow that
  precedent. Write into `Palette_Buffer` (`$FFFF821A`, CRAM line 0 base) and set
  `Palette_Dirty` (`$FFFF829A`); the per-line dirty→CRAM DMA already exists in
  `engine/system/buffers.emp`.
- **Do NOT re-index Knuckles' art.** His art stays in S3K order because his palette
  is S3K's. The generator's exclusion comment already says this.

**The foreclosure, and why it does not block you:** with a Knuckles palette in line
0, Sonic and Knuckles cannot coexist on one CRAM line. That only matters for the
**CPU follower (C3)**, which is blocked on the VRAM ruling anyway. Do not try to
solve it. Three costed options are ledgered in `docs/DEFERRED_WORK.md`.

**The rest of Task 9:** `PhysTable_Knuckles` = Sonic's row with jump force
`$680 → $600` (the ONLY delta — cite SPG/S3K), `CharDef_Knuckles` (stand box from
S3K's `Knuckles_Init`; `cd_ability = Ability_KnuxGlide` — stub it as `Ability_None`
until Task 10), `Ani_Knuckles` full table with ordinal `ensure`s, and point
`CharacterDefs[CHAR_KNUCKLES]` at it (removing the TEMP Sonic stub).
**Assert no DPLC entry exceeds 16 tiles** with an independent parser — do not trust
the generator's own assert.

**VRAM:** Knuckles' file-wide peak is 29 tiles; the shared character window at tile

## 5. STANDING RULES (all learned the hard way on this branch)

- **Emulator is CONTROLLER-ONLY.** Oracle MCP from a subagent deadlocks the arbiter.
  Subagents build and reason; they never touch it. If a diagnosis needs the
  emulator, they report BLOCKED with the exact reads wanted.
- **Oracle wedges intermittently** on heavy `press` use — `PC=SP=0xFFFFFFFF`, frozen
  frame token. `breakpoint_clear`+`reset` do NOT recover. Kill + relaunch:
  `pkill -x oracle_gui`, then `./oracle_gui <abs path>` from
  `/home/volence/sonic_hacks/oracle/linux-port/build`. Happened 3× in one session.
- **Consecutive `press` calls need a released frame between them** or the fresh-press
  edge does not re-arm. Insert a neutral press. (This masqueraded as "the hotkey is
  broken" and as "the game is hung" — both were testing artifacts.)
- **Every byte-changing parcel owes the ritual:** `SIGIL_BLOB_LEN_DRIFT=warn`,
  rebuild both sigil binaries, repin → refreeze, three gates. New `.emp` module ⇒
  `map.toml` `order` entry **plus** a sigil `ModuleSpec` with a **REAL PIN**, landed
  in the SAME change as the file (modules cannot be pre-registered).
- **Aggregate test totals, never `tail`** a `--no-fail-fast` run:
  ```bash
  cargo test -q --release --workspace --no-fail-fast 2>&1 | awk '
  /^test result/ { for(i=1;i<=NF;i++){ if($i=="passed;") p+=$(i-1); if($i=="failed;") f+=$(i-1) } }
  /^error: test failed, to rerun pass/ { print "FAILING: " $0 }
  END { printf "\nTOTAL: %d passed, %d FAILED\n", p, f }'
  ```
- **Do not shave bytes to fit a stale pin.** Re-derive the tables. Refused twice,
  correctly, on this branch.
- **`PlayerV` SST overlay**: the replay hash covers `$30..$4D` **including the unused
  bytes as boot-zero**. Address-free scalars a character never writes are fine
  (flight uses `$42`/`$43`); pointers are not; and never clear them at init — a
  clear is a write.
- `git add` exact paths only, never `-A`. Verify `git branch --show-current` before
  every commit — parallel sessions share the tree.
